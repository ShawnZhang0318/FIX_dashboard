# 每日预测销量与自动补货

S001 的 20 种商品每天北京时间 **22:00** 自动结算。打开[本地库存页](http://127.0.0.1:5174/FIX_dashboard/#/inventory)可以查看门店营业日、下次结算时间和库存历史。结算由后台服务执行，关闭浏览器也会运行。

## 销量和补货如何计算

每个商品都以最近保存的库存作为期初库存，按照以下顺序结算。

1. **预测当天需求。** 如果截至昨天有连续 29 天的销量，系统使用已训练模型。模型预测该商品整个供货周期的需求，将中位数预测（P50）除以供货天数，四舍五入得到当天预测销量。
2. **扣减库存。** 入账销量最多为期初可售整件数。例如期初有 5 件、预测需求为 8 件，则当日售出记 5 件。报表同时保留预测需求 8 件，可以查到缺货差额。
3. **自动补货。** 系统按该商品供货周期需求的第 90 百分位（P90）确定目标库存。售后库存低于目标时，模拟补足差额并按整件入库，库存充足时补货量为零。每个商品的售出、补货与结存一同保存。

**期末库存 = 期初库存 − 入账销量 + 模拟补货量。** 补货在当晚结算时入账，次日可售。预测库存用于门店演示，真实采购和供应商发货需要另行处理。

若近期快照不足，系统用项目历史数据估算同月同星期几的销量（50%）、最近八个同星期几的销量（30%）和最近 28 次观测的销量（20%）。补货参考历史连续供货周期销量的第 90 百分位和预计周期需求。页面会标明“历史销量基线”或训练模型。模型服务故障时，系统保留原库存，记录失败并重试。

## 开启和查看

首次使用先依照[项目说明](../README.md)启动本地服务，导入原始数据，为全部商品建立期初库存。本地脚本默认使用 `Asia/Shanghai` 和 `22:00`。在库存页打开“库存历史”，选择已结算的日期，即可查看各商品的期初库存、预测销量、入账销量、补货量和期末库存。旧版记录继续按各自保存的字段显示。

启用首日从当天开始。电脑关机或后台暂停期间无法准点入账，重启后会依次补算启用以来已到期的营业日。系统保留已导入的完整日期和已有扫码流水。重复处理同一日只会记账一次；当日有冲突或预测失败时，可在“日志”按服务 `worker` 检查原因。

## 接口核对

| 接口 | 可以核对的内容 |
| --- | --- |
| `GET /inventory/automation?store_id=S001` | 门店日期、结算状态、下次结算时间和最近完成日期。 |
| `GET /sales/day?business_date=YYYY-MM-DD` | 已完成的结算汇总，含当日销量和各商品明细。预测结算还包含补货总量。 |
| `GET /snapshots?store_id=S001&from=YYYY-MM-DD&to=YYYY-MM-DD` | 指定日期的商品快照。自动入账的来源以 `forecast_auto/` 开头。 |
| `GET /inventory?store_id=S001` | 每个商品最新的库存余额。 |
