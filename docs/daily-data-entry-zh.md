# 数据日期与每日售出录入

## 使用方式

1. 打开库存页。默认显示后端库存中最新的数据日期，表格及汇总显示该日期的实际库存和每日售出。
2. 使用“数据日期”查看历史记录；“最新数据”回到最新观测日期。“刷新”重新读取已保存记录，不会生成或更改数据。
3. 点击“录入每日售出与库存”。新日期默认是当前查看日期的次日，可以调整为其他非未来日期。
4. 填写每个商品当天的实际售出和实际库存。两项初始为空；实际为零时请明确输入 `0`。库存是独立观测值，系统不会再减一次销量，也不会把订购数量直接当作已到货。
5. 展开每个商品的“核对其他字段”。分类、区域、订购量、价格、折扣、天气、促销、竞品价格、季节和数据源需求基准沿用所查看日期作为录入模板；必须核对并修改为新日期的适用值。它们不会自动更新为真实新观测。
6. 勾选已核对并保存。保存成功后，库存页切换到新日期。“前往分析页面”进入新建分析；真实 Daily 分析自动使用电脑系统当天日期，不沿用库存查看日期，分析页面不提供日期选择器。

### 分析日期跟随系统时间（2026-11-25）

- 保留 Daily / Monthly 卡片和门店输入的布局。Daily 卡片显示当前电脑本地日期，不使用 UTC 日期、数据集最新日期或网址中的 `as_of_date` 参数。
- 页面跨天时自动更新；回到页面或唤醒电脑后重新读取日期，并定期检查系统时间变化。点击运行时再次读取系统日期作为请求的 `as_of_date`。
- 历史任务及结果仍显示数据库保存的原始分析日期。点击“新建分析”才进入按系统时间运行的新任务。
- 库存页仍可以按真实数据日期查询和录入历史记录。更改分析日期逻辑不会改写历史快照，也不会生成今天的数据；当天数据或必要历史不足时，后端仍拒绝分析请求。
- Mock 演示明确标记固定样例日期 `2022-06-30`；接入真实后端的 Live 模式才使用系统日期。Monthly 补货功能状态保持不变。

缺少数据的日期显示空表和未提供的数量，不会回退到其他日期或把缺失销量显示为零。当前表单按所查看日期的商品清单批量录入；部分商品缺失时，可使用已有的“每日快照传输”接口补录缺失项。

## 数据流与持久化

`手动录入 → 公共 POST /snapshots → 数据库快照 + 最新库存视图 → GET /snapshots 按日期回读 → POST /analysis-runs → Worker → 模型 → 持久化结果`

- 复用已有公共 API、请求校验、错误处理和请求关联日志，没有新增浏览器直接调用模型或写数据库的路径。
- 仍使用完整快照协议。手动记录的 `source_reference` 标记 `manual-entry`、模板快照 ID 和模板日期；`source_file_sha256` 在手动场景中表示规范化提交行 JSON 的 SHA-256，不代表存在原始 CSV 文件。
- 整批数据在一个事务中提交。门店、商品和日期重复时返回 `409`，整批回滚，不覆盖已冻结分析所引用的历史记录。此入口用于新增观测，尚未提供历史数据更正流程。
- 更新的快照日期较新时，后端更新当前库存视图；补录较早日期不会把当前库存回退。浏览器保存成功后读取服务器数据。
- 写入超时或回包无法确认时，不自动重试。“核对已保存数据”检查同一天每个商品及其提交摘要；未确认整批成功时保持提交锁定，需核对后端日志。
- Daily 预测仍受后端覆盖检查约束，通常需要全部 20 个商品和包含分析当天在内的连续 29 天记录。只把日期跳到今天不能补齐历史缺口。已有无变化商品跳过规则保持原样。
- Mock 模式仅提供原有模拟快照查询，手动录入按钮禁用；真实录入需接通后端。

## 验证

- `node --test frontend/tests/*.test.js`：包括日期筛选、缺失值与真实零值、输入范围、手动来源摘要、共享 API 传输和超时后的整批核对。
- `python -m pytest local_backend/tests/test_flow.py`：在隔离测试数据库中覆盖新日数据保存、库存日期推进、销量回读、重复拒绝、原分析冻结输入不变，以及新分析使用新销量。
- `npm run build`：前端构建检查。

测试记录使用隔离数据库。开发验证不会向正在演示的数据库填写虚构的真实销量。
